# Замена визарда завершения заявки на единое уведомление

## Контекст

Сейчас клик по кнопке действия («Заявка выполнена») для заявок в статусе
«Прибыл» / «На исполнении» запускает 3-шаговый визард
(`startCompletionFlow`, [src/requests/detail.ts:150-212](../../../src/requests/detail.ts#L150-L212)):

1. Если у заявки 0 файлов — обязательное требование прикрепить фото/видео
   (`BotState.WAITING_MEDIA`).
2. Если нет описания работ (`work_done`) — предложение добавить его
   («Написать» / «Пропустить»).
3. Финальное подтверждение «Завершить заявку?» (Да / Отмена).

Требуется заменить весь визард одним экраном-напоминанием без
принудительных шагов.

## Новое поведение

### 1. Триггер

Клик по кнопке действия (`rs:{id}`) для `completionStatuses` сразу
показывает новый экран (без проверки файлов/описания):

> ⚠️ Внимание! Убедитесь что вы внесли информацию о проделанной работе,
> добавили файлы фото или видео фиксации.

Кнопки: **«Выполнена»** / **«Внести изменения»**, использующие
существующие callback-роуты `rsc:{id}:{status}` / `rsx:{id}`
(меняются только текст экрана и подписи кнопок в `buildConfirmKeyboard`,
[src/requests/keyboards.ts:77-84](../../../src/requests/keyboards.ts#L77-L84)).

Проверки на наличие файлов и описания работ убираются полностью —
уведомление становится напоминанием, а не блокирующим требованием.

### 2. «Выполнена» (`rsc:`)

`handleStatusConfirm` меняет статус заявки через API (как сейчас), но
вместо повторной отрисовки карточки заявки — переходит к списку заявок,
вкладка **«Новые»**, переиспользуя `handleTabAction(ctx, 'new')`
из [src/requests/list.ts:103-112](../../../src/requests/list.ts#L103-L112).

Статус меняется независимо от того, добавлены ли файлы/описание.

### 3. «Внести изменения» (`rsx:`)

`handleStatusCancel` не меняется по сути — возвращает на карточку заявки
(«Карточка дома» / «Выполненная работа» / «Добавить фото и видео» /
кнопка действия / «К списку заявок»), как сейчас работает «Отмена».

### 4. Чистка кода, ставшего мёртвым

Поскольку обязательные шаги визарда убираются, следующее становится
неиспользуемым и удаляется:

- `promptWorkDoneOrConfirm`, `handleWorkDoneSkip`,
  `buildWorkDoneStepKeyboard`, роут `rws:` в
  [src/setup.ts](../../../src/setup.ts).
- Поле `completionFlow` в типе сессии
  ([src/types/session.ts:8](../../../src/types/session.ts#L8)) и все его
  использования, включая ветки `wasCompletionFlow` в `handleMediaDone`
  и `handleIncomingComment` (эти функции упрощаются до единственного
  пути — просто перерисовывают карточку заявки).
- `startCompletionFlow` схлопывается в прямой вызов нового экрана
  (без установки `WAITING_MEDIA` и `completionFlow`).

Не удаляется (используется независимо, вне визарда):

- `BotState.WAITING_MEDIA`, `handleAddMediaButton`, `handleMediaDone` —
  используются кнопкой «Добавить фото и видео» на карточке заявки.
- `handleCommentButton` / `WAITING_COMMENT` — используются кнопкой
  «Выполненная работа» на карточке заявки.

## Затронутые файлы

- `src/requests/detail.ts` — основная логика (`handleStatusAction`,
  `handleStatusConfirm`, `handleStatusCancel`, удаление визардных шагов).
- `src/requests/keyboards.ts` — текст и подписи кнопок
  `buildConfirmKeyboard`, удаление `buildWorkDoneStepKeyboard`.
- `src/setup.ts` — удаление роута `rws:`.
- `src/types/session.ts` — удаление поля `completionFlow`.

## Не входит в объём задачи

- Карточка дома, добавление файлов, описание работ — экраны не
  меняются, только точка входа/выхода из них.
- Логика для остальных статусов (`MINIMAL_KEYBOARD_STATUSES` и прочие)
  не затрагивается.
